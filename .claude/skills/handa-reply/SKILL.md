# 繁田の代筆で保護者に返信する（handa-reply）

繁田本人が書いた返信2通を見本に、**短く・軽く・相手を立てて・ドアを開けておく**返事を書く。
AIが書くと「中身を足す」方向に走る。本人は「減らす」方向で書く。これが一番の違い。

## 必読

1. `reply_guide.md` — 型と、やってはいけないこと
2. `examples.md` — 本人の見本2通（採用）と、没になったAI案3通（反面教師）

## 鉄則

1. **送らない。** 出すのは返信案だけ。送信・下書き保存・配信システムへの投入は繁田が行う
2. **捏造しない。** 本文に入れる事実は、相手のメールに書いてあることと、依頼者（繁田または担当者）から渡された事実だけ。「教室からも聞いていました」「よく見てきました」「記録が残っています」のような確認していないことを書かない
3. **繁田が決めることを、AIが決めない。** 招待に行くか、割引するか、会うか、のような判断は本人に聞く。「予定を確認してみますね」のような保留文でごまかさない。判断が未定なら ［行く／行けない を繁田が決める］ とプレースホルダで残す
4. **1案だけ。** 3案は要らない。150〜300字
5. **メルマガの型を持ち込まない。** 本人の出来事→橋→教訓、持論、体験談、研究の引用は返信には不要

## 手順

1. 相手のメールを読み、**話題を数える**（例: 同感・近況・子の様子・招待・季節の挨拶・追伸）
2. **返す話題を1〜2つに絞る**。相手が一番伝えたかったこと（報告・決断・招待）を優先。2つにまとめられるなら1行にまとめる
3. 相手との関係を判断して可変部分を選ぶ（初対面に近い／長く読んでいる／元塾生の家庭）
4. `reply_guide.md` の型で書く。核（本音1行／短い肯定／励まし＋「！」／締め）は必ず入れる
5. 返事が要る用件（招待・依頼）は、本人の判断を確認したうえで、理由を添えて一文で返す。断ったら相手（の子）を立てる一言を添える
6. 相手に追伸があれば、追伸で軽く返してよい（任意）
7. 出す前に `reply_guide.md` §4「やらない」の表で自己点検し、該当があれば削る
8. 返信案の下に、依頼者に確認したいことがあれば箇条書きで添える（最大3つ）

## 出力の形

```
（返信案 本文のみ。宛名から署名まで）

---
確認したいこと:
- 11/8 の招待は、行く／行けない のどちらで書きますか
```
