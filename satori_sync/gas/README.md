# 新規状況表v2.0 → SATORI 自動連携（GAS）

新規状況表v2.0 に組み込むスクリプトです。30分ごとに「新規状況表v2.0_マスター」を読み、
前回送った内容から変わった人だけを SATORI カスタマーバルクAPI で更新します。

| 状況 | SATORI の「現在の状態」（custom_situation） | タグ「新規_未決元在」 |
|------|------|------|
| 前月末より後に問合せ・面談・体験などの対応あり | **対応中**（未決・元在を解除） | 外す |
| 再入会にチェック / 9/1 以降の入会 | 在籍 | 外す |
| 退会日あり / 在籍ステータスが元在 | 元在 | 6/1 以降の問合せなら付ける |
| 前月末までに対応が止まっている | 未決 | 6/1 以降の問合せなら付ける |
| 送付禁止フラグ | 配信許可を「拒否」 | — |

- 毎月1日になると締め日（前月末）が進むため、前月に対応が止まった人が自動で未決になります。
- 既存のGAS（`handleBackgroundSync` などが更新する カスタマーステータス `custom_status`）とは別の項目なので干渉しません。
  既存の列・関数は変更せず、送った内容は新しいシート「SATORI連携ログ」に記録します。
- 判定ロジックは `SatoriLogic.gs`（Node でテスト可能: `node test_logic.js`）、
  シート・API とのやり取りは `SatoriSync.gs` にあります。

## 設置手順

1. **SATORI**: カスタム項目「現在の状態」に選択肢 **「対応中」** を追加する。
2. **Apps Script**（新規状況表v2.0 の「拡張機能 → Apps Script」）でファイルを2つ追加し、
   `SatoriLogic.gs` と `SatoriSync.gs` の中身をそれぞれ貼り付けて保存する。
3. `satoriInitLog` を1回実行する。
   9/29 に手作業で取り込んだ内容を「送信済み」として記録します（APIは呼びません）。
4. **情報獲得経路の対応表**: バルクAPIでは情報獲得経路（collection_route）が必須のため（2026/09/29 のテストで確認）、
   新しいシート「SATORI登録済み」を作り、SATORIのカスタマーエクスポートの email を A列、collection_route を B列に貼る。
   スクリプトプロパティ `SATORI_SEND_ROUTE` を `true` にする。
   - 送信時は SATORI 登録済みの値をそのまま送るので、既存の情報獲得経路は変わりません。
   - シートに無い人・経路が空の人は、既存の `handleBackgroundSync` と同じく「なにで知ったか」（空なら SATORI通常問い合わせフォーム）を送ります。
5. **API の動作確認**: スクリプトプロパティ `SATORI_TEST_EMAIL` にテスト用カスタマーのメールアドレスを入れ、
   `satoriTestOne` を実行して実行ログを確認する。`failed_rows` が空なら成功。
   SATORI でそのカスタマーの現在の状態が「対応中」になり、情報獲得経路が変わっていないことを確認。
6. `satoriSetup` を1回実行する（30分ごとのトリガーを登録）。
7. しばらくは **お試しモード** で動きます（SATORI には送らず、「SATORI連携プレビュー」シートに送る予定の内容を書き出すだけ）。
   内容に問題がなければ、スクリプトプロパティ `SATORI_DRY_RUN` を `false` にすると送信が始まります。

APIキーは既存のスクリプトプロパティ `SATORI_API_KEY` / `SATORI_SECRET_KEY` / `COMPANY_KEY` / `COMPANY_SECRET` を使います。

## シート

| シート | 内容 |
|--------|------|
| SATORI連携ログ | メールアドレスごとに、最後に送った現在の状態・配信許可・タグと送信日時。処理中・失敗の情報もここに残ります。 |
| SATORI連携プレビュー | お試しモード中に、次に送る予定の変更を書き出します。 |
| SATORI登録済み | A列: メールアドレス、B列: SATORIの情報獲得経路。送信時の情報獲得経路に使います。`SATORI_CONF.restrictToRegistry` を true にすると、ここに無い人には送りません。 |

失敗が3回続いた人は自動では送り直しません。ログの「失敗回数」を 0 に戻すと再送します。

## 設定（`SatoriSync.gs` の `SATORI_CONF`）

- `tagInquirySince`: タグを付ける問合日の下限（既定 2026-06-01）
- `enrolledWriteSince`: 在籍を書き込む入会日の下限（既定 2026-09-01。それより前の入会は現役か分からないため触れない）
- `yearInferenceAnchor`: 年なし（MM/DD）の問合日の年推定の基準日
